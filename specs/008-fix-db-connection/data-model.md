# Phase 1 Data Model: Fix Missing Database Connection in Local Dev

**Branch**: `008-fix-db-connection` | **Date**: 2026-05-27
**Revision**: 2 — same outcome as revision 1 (no entities), updated
to describe the configuration "entity" under the
`@netlify/vite-plugin` approach.

## No domain entities

This feature has no domain data model. It does not introduce, modify,
or remove any database tables, columns, indexes, constraints, or
materialized views. It does not introduce, modify, or remove any
in-memory entities, types, or interfaces in application code.

The Postgres schema referenced by `getDatabase()` is unchanged. The
migrations in `netlify/database/migrations/` are unchanged. No new
migration is created by this work.

## Configuration "entity" (recorded for completeness)

The feature spec lists three "Key Entities":

- **Database Connection (local dev)** — modeled as the
  `NETLIFY_DB_URL` value injected into the functions runtime by
  `@netlify/vite-plugin` at Vite-server start. The value is
  generated by `@netlify/database-dev` (the embedded PGlite driver
  in `@netlify/dev`) and points at a local Postgres-wire endpoint
  backed by the directory `.netlify/db/`. The value lives only in
  the running Vite/functions process's memory; it is never written
  to any file. The on-disk PGlite directory IS per-developer state
  — it is gitignored (`.gitignore:8`, `.netlify`) and rebuilt at
  startup if missing.
- **Local Dev Stack** — a single Vite process listening on
  `127.0.0.1:8888`. `@netlify/vite-plugin`'s middleware intercepts
  `/api/*` and `/.well-known/*` and routes them to the local
  Netlify Functions runtime (embedded in-process by
  `@netlify/functions-dev`). The same in-process orchestrator
  provisions PGlite and injects `NETLIFY_DB_URL` into the function
  handler's environment.
- **Deployed Runtime** — the Netlify-managed Functions runtime in
  production / preview / branch. Already receives `NETLIFY_DB_URL`
  from Netlify's Database integration. UNCHANGED by this work.

These are configuration concerns, not data-model entities, and they
do not produce schemas, types, or migration artifacts.

## Validation rules

There is no developer-supplied configuration to validate.
`@netlify/vite-plugin`'s database feature is enabled by default
(`@netlify/dev/dist/main.js:331`: `database: options.database?.enabled !== false`),
so simply registering `netlify()` in `vite.config.js` is enough.

The plugin enforces one operational rule: if PGlite fails to start
(e.g. corrupted `.netlify/db/`, disk full), it logs
`Failed to start Netlify Database locally: <error>` via the Vite
logger AND does not set `NETLIFY_DB_URL`. The first DB-backed
request then surfaces `MissingDatabaseConnectionError` from
`@netlify/database` itself. The startup log line is the early signal
(FR-003, FR-004).

The plugin does NOT validate the schema state of the local PGlite —
applying `netlify/database/migrations/**/*.sql` to it is a separate
step (`npx netlify db migrations apply`). A missing-migrations state
surfaces from Postgres as `relation "<name>" does not exist`,
visually distinct from `MissingDatabaseConnectionError` (FR-004).

## State transitions

None. There is no state machine in this feature. The PGlite database
itself has lifecycle (created on first start, persisted to
`.netlify/db/`, destroyed by `npx netlify db reset` or by removing
the directory), but that lifecycle is owned by
`@netlify/database-dev` and is not modeled in this spec.
